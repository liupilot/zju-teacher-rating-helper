## 摘要

选课老师评价助手是一个运行在 Chrome / Edge 浏览器中的 Manifest V3 扩展。它解决了一个具体的日常痛点：浙江大学学生使用选课系统时，想查看某位教师的评价，必须复制教师姓名、打开查老师网站、粘贴搜索，遇到多位教师时还要反复重复这一流程。

本扩展把这条链路压缩成"打开选课页即可看到答案"：内容脚本自动识别教学班表格中的教师姓名，在每个姓名旁注入"查询评价"按钮；后台 Service Worker 拉取并解析查老师网站的公开数据；页面直接显示评分与评价人数标签；点击标签可在弹窗中查看综合评分、评价人数、开设课程、最新评价和评价关键词；点击"查看完整评价"可跳转到查老师网站并自动填充搜索框。

本文从项目目的、总体架构、模块实现、关键逻辑、涉及知识、安装使用和迭代复盘七个方面，完整说明该扩展的设计与实现。

## 1. 项目概述

### 1.1 项目背景

浙江大学选课系统（`https://zdbk.zju.edu.cn/`）在课程教学班表格中展示任课教师姓名，但页面上没有教师口碑信息。教师评价数据分散在第三方站点"查老师"（`https://chalaoshi.netlify.app/`）上，且以静态 CSV / JSON 文件形式公开，没有后端 API 可供选课页直接调用。

当学生面对多门课程、多位教师时，手动逐个查询的体验很差：

- 需要不断复制姓名、切换标签页、粘贴搜索；
- 同名教师无法快速区分，容易点错；
- 教师数量多时，重复劳动多，容易遗漏；
- 课程列表是动态加载的，页面结构随时可能变化，需要持续监听。

### 1.2 项目目的

本项目希望达到以下目标：

- 在选课页中直接展示每位教师的评分与评价人数，减少复制粘贴和跳站操作；
- 提供教师详情弹窗，展示综合评分、开设课程、最新评价与高频关键词；
- 对同名教师提供候选列表，由用户确认，不擅自替用户选择；
- 支持跳转到查老师网站并自动搜索，方便查看完整评价；
- 适配选课页动态加载和内容区重建，保证教师识别不中断；
- 只请求必要的数据，权限最小化，不上传任何用户数据。

### 1.3 功能范围

本报告对应的扩展版本为 0.2.0，核心功能包括：

- 自动识别教学班表格中的教师姓名；
- 教师姓名旁显示"⭐ 查询评价"按钮与评分标签；
- 评分标签包含"查询中 / 已找到 / 同名 N 位 / 未找到 / 查询失败"五种状态；
- 点击标签打开插件自己的评价弹窗（Shadow DOM 实现）；
- 弹窗展示综合评分、评价人数、开设课程、最新 5 条评价、评价中常提到关键词；
- 同名教师候选列表，点击候选后按学院重新查询；
- "查看完整评价"跳转到查老师网站并自动填充搜索框；
- 查询结果在 `chrome.storage.local` 中缓存 24 小时；
- Service Worker 提供查询去重、20 秒超时、失败可重试等机制。

### 1.4 技术路线概览

项目采用浏览器扩展标准架构，不依赖构建工具或第三方运行时：

- **声明层**：`manifest.json` 声明权限、后台脚本、内容脚本与匹配域名；
- **页面层**：针对选课页的内容脚本负责 DOM 识别、按钮注入、评分渲染和弹窗交互；
- **数据层**：针对查老师页的内容脚本负责自动搜索填充；
- **后台层**：Service Worker 负责消息路由、数据拉取、CSV/JSON 解析、匹配逻辑与缓存；
- **存储层**：`chrome.storage.local` 保存 24 小时查询缓存。

## 2. 总体架构与数据流

### 2.1 三层架构

扩展由三层组成，职责边界清晰：

| 层级 | 所在位置 | 职责 |
|------|----------|------|
| 内容脚本（选课页） | `content/` 下的 7 个 JS 文件 + 1 个 CSS | 识别教师、注入按钮、渲染评分、打开弹窗、分析关键词 |
| 内容脚本（查老师页） | `content/chalaoshi-search.js` | 读取 URL 参数并自动填充搜索框 |
| 后台 Service Worker | `background/service-worker.js` | 消息路由、查询编排、20 秒超时、请求去重 |
| 后台服务模块 | `background/teacher-service.js` | 拉取并解析数据、教师匹配、评论与绩点组装 |
| 后台缓存模块 | `background/cache-service.js` | 24 小时查询缓存与清缓存 |
| 存储 | `chrome.storage.local` | 持久化查询结果，键为 `zjuTeacherHelperCache` |

### 2.2 数据来源

查老师网站以静态文件公开数据，扩展直接读取这些文件：

| 数据文件 | 内容 | 用途 |
|----------|------|------|
| `teachers.csv` | 教师 id、姓名、学院、热度、评分人数、评分、拼音、拼音缩写 | 教师身份匹配与评分摘要 |
| `gpa.json` | 教师姓名到课程数组的映射，每项含课程、绩点、人数、通过率 | 弹窗中的"开设课程" |
| `comment_学院.csv` | 评论 id、老师 id、姓名、时间、点赞点踩数据、内容 | 最新评价与关键词分析 |

### 2.3 端到端数据流

一次完整查询的链路如下：

```text
选课页打开 / DOM 变化
        │
        ▼
content.js（MutationObserver + 防抖 + 看门狗）
        │ 扫描
        ▼
teacher-detector.js（定位 table.table.table-hover、td.jsxm、拆分多教师）
        │ 记录
        ▼
query-button.js（注入"⭐ 查询评价"按钮，状态机渲染）
        │ 收集姓名
        ▼
rating-display.js（去重、LRU 查询缓存、5 并发滑动限流）
        │ chrome.runtime.sendMessage
        ▼
service-worker.js（先查 storage 缓存 → 未命中走 pendingRequests 去重 → 20s 超时）
        │ 调用
        ▼
teacher-service.js（拉取 teachers.csv / gpa.json / comment_学院.csv）
        │ 姓名+学院匹配 → 组装结果
        ▼
cache-service.js（found / ambiguous 写入 24h 缓存）
        │ 返回
        ▼
rating-display.js → query-button.js（更新评分标签）
        │ 点击标签
        ▼
review-modal.js（Shadow DOM 弹窗：评分、课程、评价、关键词、同名候选）
        │ 点击"查看完整评价"
        ▼
chalaoshi-search.js（查老师页按 zju_teacher 参数自动填充搜索框）
```

## 3. 模块实现方法

### 3.1 入口与清单：`manifest.json`

清单文件是扩展的入口，声明了版本 0.2.0、扩展名"浙江大学选课老师评价助手"和最小权限：

```json
{
  "manifest_version": 3,
  "name": "浙江大学选课老师评价助手",
  "version": "0.2.0",
  "permissions": ["storage"],
  "host_permissions": ["https://chalaoshi.netlify.app/*"],
  "background": {
    "service_worker": "background/service-worker.js"
  },
  "content_scripts": [
    {
      "matches": ["https://zdbk.zju.edu.cn/*"],
      "css": ["content/teacher-helper.css"],
      "all_frames": true,
      "js": [
        "content/teacher-detector.js",
        "content/query-button.js",
        "content/teacher-service-client.js",
        "content/rating-display.js",
        "content/keyword-analyzer.js",
        "content/review-modal.js",
        "content/content.js"
      ],
      "run_at": "document_idle"
    },
    {
      "matches": ["https://chalaoshi.netlify.app/*"],
      "js": ["content/chalaoshi-search.js"],
      "run_at": "document_idle"
    }
  ]
}
```

关键设计：

- `permissions` 只申请 `storage`，没有 `tabs`、`webRequest` 等多余权限；
- `host_permissions` 只覆盖查老师站点，因为选课页数据读取不需要网络权限；
- 选课页内容脚本设置 `all_frames: true`，兼容选课页可能存在的 iframe 结构；
- 两个站点分别注入不同脚本，职责互不干扰。

### 3.2 选课页内容脚本

#### `content.js`：动态监听与扫描编排

这是整个插件的"调度中枢"，负责监听 DOM 变化并协调其他模块：

- 用 `MutationObserver` 观察 `document.documentElement`，配置包含 `childList`、`subtree`、`attributes`、`characterData`；
- 通过 `isTeacherRelevantMutation` 过滤无关变化：插件自身注入的按钮、弹窗 Shadow DOM 不触发重扫，只有教学班表格相关变化才进入队列；
- 采用防抖策略：`SCAN_DEBOUNCE_MS = 300`，若 300 毫秒内没有新变化则执行扫描；为避免高频 DOM 重建导致扫描无限推迟，另设 `MAX_FLUSH_DELAY_MS = 1500` 强制刷新；
- `runTeacherScan` 每次扫描前调用 `resetProcessedRows()`，保证重建后的表格行可被重新识别；
- 提供页面结构诊断：若检测到表格和数据行但识别不到教师单元格，会在控制台提示"选课页面结构可能已变化"；
- 用 1 秒间隔的"根节点看门狗"（`WATCHDOG_INTERVAL_MS = 1000`）检查 `document.documentElement` 是否被替换，必要时重新挂载观察器并主动重扫。

核心常量：

```javascript
const SCAN_DEBOUNCE_MS = 300;
const MAX_FLUSH_DELAY_MS = 1500;
const WATCHDOG_INTERVAL_MS = 1000;
const TABLE_SELECTOR = "table.table.table-hover";
```

#### `teacher-detector.js`：教师识别

识别逻辑刻意选择"稳定锚点"而不是脆弱的完整 DOM 路径：

- 通过表头行查找文本恰好为"教师"的 `th`，定位教师列；
- 优先取 `tbody tr.body_tr`，找不到再退化到 `tr.body_tr`；
- 实际定位教师单元格使用 `td.jsxm`：因为真实表格行中存在隐藏列（如 `td.xkkh`），表头序号不能直接对应单元格序号，必须用真实出现的类名定位；
- `extractTeacherNames` 遍历单元格子节点，以 `<br>` 为分隔符拆分多位教师，同时跳过插件自己注入的按钮文本，避免把按钮文字误当成姓名；
- 用 `WeakSet` 记录已处理行，防止重复注入；提供 `resetProcessedRows()` 供重建后重置。

```javascript
// 真实表格的行内存在隐藏列，表头序号不能直接对应单元格序号，
// 因此用真实出现的 td.jsxm 定位教师单元格。
const cell = row.querySelector("td.jsxm");
```

#### `query-button.js`：按钮注入与状态机

该模块负责创建查询按钮并维护五种状态：

- 按钮使用 `<span>` 加 `role="button"`、`tabindex="0"`，支持鼠标点击和键盘 Enter / Space 触发；
- 初始文案为"⭐ 查询评价"，`title` 中写明教师姓名；
- 状态类定义：`loading`（查询中…）、`found`（`⭐ 评分 💬 人数`）、`ambiguous`（`同名 N 位`）、`notFound`（未找到）、`error`（查询失败）；
- 评分格式化固定保留两位小数；
- `inject` 先移除已不存在的旧按钮（防止 DOM 重建后重复注入），再按姓名去重；
- 按钮插入位置：如果教师姓名是独立文本节点，插在文本节点之后；否则追加到容器末尾。

#### `rating-display.js`：查询去重与并发限流

这是性能关键模块，包含三个机制：

1. **LRU 语义查询缓存**：`queries` Map 保存进行中/已完成的查询 Promise，命中时删除并重新插入以刷新位置；超过 `MAX_QUERY_CACHE_SIZE = 200` 时淘汰最久未使用项，内存有界；
2. **失败可重试**：`getQueryPromise` 的 catch 中执行 `queries.delete(name)`，失败结果不会永久留在缓存里，下次刷新会重新查询；
3. **5 并发滑动限流**：`MAX_CONCURRENT_QUERIES = 5`，任务进入队列，`drainPendingQueries` 在任务完成或失败后立即补位，避免 15 位教师同时发出 15 个请求造成卡顿。

```javascript
function drainPendingQueries() {
  while (
    activeQueryCount < MAX_CONCURRENT_QUERIES &&
    pendingQueryTasks.length > 0
  ) {
    const { task, resolve, reject } = pendingQueryTasks.shift();
    activeQueryCount += 1;
    Promise.resolve()
      .then(task)
      .then(
        (value) => {
          activeQueryCount -= 1;
          resolve(value);
          drainPendingQueries();
        },
        (error) => {
          activeQueryCount -= 1;
          reject(error);
          drainPendingQueries();
        }
      );
  }
}
```

#### `teacher-service-client.js`：消息协议封装

内容脚本不能直接访问后台数据，因此该模块把 `chrome.runtime.sendMessage` 封装成 Promise：

- `queryTeacher(name, options)` 发送 `ZJU_TEACHER_HELPER_QUERY` 消息，携带姓名、学院与是否包含评论；
- `clearCache()` 发送 `ZJU_TEACHER_HELPER_CLEAR_CACHE` 消息；
- 统一处理 `chrome.runtime.lastError` 和 `response.ok === false` 两种情况，保证调用方只会得到 `resolve(data)` 或 `reject(error)`。

#### `keyword-analyzer.js`：本地关键词规则

关键词分析是纯本地规则，不调用任何模型：

- 内置 25 条中文关键词，每条标注 `positive`（如"讲课清楚""认真""负责""给分不错"）或 `negative`（如"作业多""给分严格""很水""念PPT"）；
- 对每条评论全文做小写匹配，统计每个关键词出现次数；
- 按出现次数降序排列，默认返回前 8 个关键词；
- 产品文案刻意使用"评价中常提到"而不是"优点/缺点"，避免把规则统计包装成客观事实。

#### `review-modal.js`：Shadow DOM 弹窗

弹窗是插件内最复杂的 UI：

- 宿主元素挂载在 `document.body`，内部使用 `attachShadow({ mode: "open" })`，样式通过 Shadow DOM 隔离，不污染选课页；
- 结构为"遮罩 + 卡片"，卡片包含 sticky 头部、正文和底部链接；
- 打开时先显示"正在加载评价"，随后根据查询结果渲染四种状态：找到、同名候选、未找到、查询失败；
- 找到时展示综合评分、评价人数、开设课程、最新 5 条评价（`MAX_REVIEWS = 5`）和关键词标签；
- 同名教师渲染候选按钮，点击后以该教师学院重新查询；
- 支持点击遮罩关闭、点击 `×` 关闭、按 `Escape` 关闭；
- "查看完整评价"链接使用 `target="_blank"` 和 `rel="noopener"`，跳转到带 `zju_teacher` 参数的查老师网址。

### 3.3 后台 Service Worker

#### `service-worker.js`：消息路由与查询编排

后台通过 `importScripts` 加载两个服务模块，只做编排不做业务：

- `chrome.runtime.onMessage` 分发两种消息：查询与清缓存；
- 查询流程先读缓存，命中直接返回；未命中再走 `getOrStartPendingQuery`；
- `pendingRequests` Map 以 `cacheKey(name, college, includeReviews)` 为键，复用进行中请求，避免相同查询并发重复请求；
- `finally` 保证成功与异常路径都会清理 pending 条目；
- 外层 `withTimeout` 统一设置 20 秒超时（`QUERY_TIMEOUT_MS = 20000`），覆盖缓存读取后的完整查询流程；
- 只有 `found` 和 `ambiguous` 结果写入缓存，`not_found` 与失败不缓存，允许后续重试。

```javascript
function withTimeout(promise, timeoutMs, label) {
  return new Promise((resolve, reject) => {
    const timer = setTimeout(() => {
      reject(new Error(`${label}超时`));
    }, timeoutMs);
    promise.then(
      (value) => {
        clearTimeout(timer);
        resolve(value);
      },
      (error) => {
        clearTimeout(timer);
        reject(error);
      }
    );
  });
}
```

#### `teacher-service.js`：数据拉取与解析

这是数据层核心，包含以下实现：

**CSV 解析器（自写）**：`parseCSV` 手工实现了一个支持标准转义规则的解析器，能处理：

- 双引号包裹的字段与字段内换行；
- `""` 转义的双引号；
- CRLF 与 LF 换行；
- 空行过滤；
- 调用方统一用 `text.replace(/^\uFEFF/, "")` 去掉 UTF-8 BOM。

**表头映射**：`toObjects` 将行数组按固定表头数组映射为对象，缺失字段补空字符串。

**三层加载缓存**：

- `loadTeachers()`：单例缓存 + 进行中 Promise 缓存，失败时清 Promise 缓存以便重试；
- `loadGpaMap()`：同上；
- `loadCollegeComments(college)`：结果缓存 + 进行中 Promise 缓存，成功后写入结果，失败时删除进行中缓存。

**教师匹配策略**：`matchTeacher` 先按姓名精确过滤，再按学院消歧（详见第 4 章）。

**结果组装**：`queryTeacher` 依次组装评分摘要、开设课程与评论：

- 绩点数据来自 `gpa.json`，键优先取姓名原文，其次取大写姓名；
- 绩点加载失败不阻塞主查询（try/catch 吞掉）；
- 评论按"老师 id"从学院评论 CSV 中过滤，按发表时间倒序排列，默认取前 20 条（`DEFAULT_REVIEW_LIMIT = 20`），弹窗展示时再取前 5 条；
- 评论加载失败时降级为空数组，主结果仍然返回；
- 结果统一包含 `status`、`confidence`、`name`、`college`、`rating`、`reviewCount`、`courses`、`reviews`、`url`、`updatedAt` 字段。

#### `cache-service.js`：24 小时持久化缓存

缓存模块把查询结果写入 `chrome.storage.local`：

- 存储键为 `zjuTeacherHelperCache`，值为"缓存键 → { fetchedAt, data }"的映射；
- 缓存键格式为 `姓名::学院::模式`，模式区分 `summary` 与 `reviews`，所以带评论与不带评论的查询不会互相污染；
- 读取时检查 `CACHE_TTL_MS = 24 * 60 * 60 * 1000`，超期视为未命中；
- `clearCache()` 删除整个存储键，供调试使用；
- 同样提供 `module.exports` 出口，便于测试。

### 3.4 查老师页内容脚本：`chalaoshi-search.js`

当用户点击"查看完整评价"跳转到查老师网站时，页面 URL 携带 `zju_teacher` 参数：

- `init` 用 `URLSearchParams` 读取参数；
- 若搜索框（`id="search"`）已存在，直接填入教师姓名并派发 `input` 事件触发站点搜索逻辑；
- 若搜索框尚未渲染，启动一个最大等待 10 秒（`WAIT_TIMEOUT_MS = 10000`）的 MutationObserver，等输入框出现后自动填充；
- 10 秒超时后停止监听，避免永久占用观察器。

### 3.5 样式与可访问性：`teacher-helper.css`

查询按钮样式独立成文件，仅注入选课页：

- 默认样式为浅金色边框的胶囊按钮，固定 `min-width: 68px`，保证五种状态文案切换时布局不跳动；
- 悬停与键盘聚焦（`:focus-visible`）有明显视觉反馈；
- 五种状态各配一套配色：加载灰、找到绿、同名金、未找到灰、失败红；
- 按钮采用 `display: inline-flex` 与 `white-space: nowrap`，避免影响教师姓名换行。

## 4. 关键逻辑与设计决策

### 4.1 教师匹配与同名消歧

匹配策略是"姓名精确 + 学院消歧 + 保守降级"：

| 条件 | 结果 | 置信度 |
|------|------|--------|
| 姓名无匹配 | `not_found` | none |
| 有学院且学院内唯一匹配 | `found` | high |
| 有学院且学院内多个匹配 | `ambiguous`（候选为学院内） | medium |
| 有学院但学院内无匹配 | `ambiguous`（候选为全部同名者），不跨学院自动选择 | medium |
| 无学院且唯一匹配 | `found` | medium |
| 无学院且多个匹配 | `ambiguous` | medium |

设计意图：同名教师绝不自动选择；即使提供了学院但没有匹配项，也不擅自选中其他学院的教师，宁可不精确，不可选错人。

### 4.2 三层缓存与失败可重试

项目中存在三层缓存，各司其职：

| 层级 | 位置 | 作用 |
|------|------|------|
| 页面级 LRU | `rating-display.js` 的 `queries` | 同页重复查询复用 Promise，上限 200，失败即删 |
| 后台请求级 | `service-worker.js` 的 `pendingRequests` | 并发消息去重，`finally` 清理 |
| 数据级 | `teacher-service.js` 单例缓存 | `teachers.csv`、`gpa.json`、学院评论只拉一次 |
| 持久化级 | `cache-service.js` storage | 跨页面/跨会话复用 24 小时 |

失败路径统一遵循"失败不缓存、清掉进行中记录"的原则，保证网络抖动后能自动重试，不会永久卡死。

### 4.3 并发控制

浏览器对同一域名有并发连接数限制，教师较多时一次性发全部请求会排队卡顿。`rating-display.js` 选择队列式滑动限流而非简单分批：

- 固定同时最多 5 个请求；
- 任务完成或失败立即从队列补位，不被批内最慢请求拖累；
- 比"每批 5 个整批等待"的批处理方案更平滑。

### 4.4 DOM 动态适配与重建自愈

选课页是动态单页应用，课程展开、翻页、"查询教学班"都可能重建内容区。插件通过三重机制适配：

1. **MutationObserver + 防抖 + 最大延迟**：合并短时间高频变化，同时保证扫描不会无限推迟；
2. **根节点看门狗**：每秒检查 `document.documentElement` 是否被替换，被替换则断开旧观察器、挂载新观察器并主动重扫；
3. **幂等重扫**：扫描前重置 `WeakSet`，注入前清理旧按钮，避免重建后重复注入。

另外 `isOwnNode` 会过滤插件自身注入的节点和弹窗 Shadow DOM，防止观察器重挂后自我触发死循环。

### 4.5 容错与降级

各数据源允许独立失败：

- 绩点数据加载失败：不阻塞主查询，课程列表为空；
- 评论加载失败：评论为空数组，弹窗显示"该教师暂无评价"；
- 查老师站点不可达：查询标签显示"查询失败"，用户仍可点击按钮在弹窗内重试；
- 查询 20 秒超时：`withTimeout` 拒绝 Promise 并返回错误结果；
- 页面结构变化：控制台输出诊断信息提示维护识别规则。

### 4.6 权限最小化与隐私

- 只申请 `storage` 权限，不申请 `tabs`、历史记录、网页内容读写之外的任何权限；
- `host_permissions` 只包含查老师数据域；
- 扩展不收集、不上传用户行为数据；
- 关键词统计完全在本地规则上完成，不调用外部 AI；
- 弹窗链接使用 `rel="noopener"`，防止反向标签页劫持。

### 4.7 键盘可访问性

- 查询按钮有 `role="button"`、`tabindex="0"`，支持 Enter 与 Space 激活；
- 弹窗关闭按钮有 `aria-label="关闭"`；
- 支持 Escape 关闭弹窗；
- 焦点样式通过 `:focus-visible` 明确呈现。

## 6. 安装与使用

### 6.1 安装前置条件

- 一台 Windows 电脑，安装 Chrome 或 Edge 浏览器；
- 扩展源码目录为 `zju-teacher-rating-helper`（本报告对应版本）；
- 无需安装 Node.js、npm 或其他依赖，扩展是纯静态文件。

### 6.2 Chrome 安装步骤

1. 打开 Chrome，地址栏输入 `chrome://extensions` 并回车；
2. 打开右上角"开发者模式"开关；
3. 点击"加载已解压的扩展程序"；
4. 选择 `zju-teacher-rating-helper` 文件夹；
5. 确认扩展列表中显示"浙江大学选课老师评价助手"，版本为 0.2.0。

### 6.3 Edge 安装步骤

1. 打开 Edge，地址栏输入 `edge://extensions` 并回车；
2. 打开左侧"开发人员模式"开关；
3. 点击"加载解压缩的扩展"；
4. 选择 `zju-teacher-rating-helper` 文件夹。

### 6.4 使用与验证流程

1. 安装后打开 `https://zdbk.zju.edu.cn/`；
2. 展开任意课程，等待教学班表格出现；
3. 教师姓名旁应出现"⭐ 查询评价"按钮，随后自动显示评分标签，如 `⭐ 4.50 💬 12`；
4. 点击评分标签，打开插件弹窗，检查综合评分、评价人数、开设课程、最新 5 条评价和"评价中常提到"关键词；
5. 若显示"同名 N 位"，点击任一候选查看对应教师详情；
6. 点击"查看完整评价"，确认新标签页跳转到查老师网站并自动填充教师姓名；
7. 显示"未找到"表示查老师数据集中暂无该教师；显示"查询失败"可稍后重试。

### 6.5 调试与清缓存

- 在扩展详情页点击"Service Worker"打开后台控制台，可查看查询日志；
- 在 Service Worker 控制台执行 `ZJUTeacherCache.clearCache()` 可清空 24 小时缓存；
- 在选课页控制台可查看 `[ZJU Teacher Helper]` 前缀的扫描与注入日志。

### 6.6 常见问题排查

| 现象 | 可能原因与处理 |
|------|----------------|
| 看不到查询按钮 | 扩展未加载，或当前页面不是 `https://zdbk.zju.edu.cn/`，或课程尚未展开 |
| 显示"查询失败" | 查老师网站暂时不可达或网络异常，稍后会自动重试 |
| 显示"同名 N 位" | 数据集中存在多位同名教师，需在弹窗中选择 |
| 显示"未找到" | 查老师数据集中暂无该教师 |
| 控制台提示页面结构可能变化 | 选课页 DOM 结构变更，需要更新识别规则 |

## 7. 迭代复盘：审查后的六项修改

项目经历了代码审查（2026-08-24）与两轮修改（2026-08-25、2026-08-28），以下按问题优先级概述实际落地结果，详细方案对比见 `MODIFICATION_REPORT.md`。

| 问题 | 优先级 | 修复文件 | 实际方案 |
|------|:------:|----------|----------|
| 并发控制缺失导致卡顿 | 高 | `rating-display.js` | 队列式滑动限流，最多 5 并发 |
| 同一学院评论 CSV 被反复拉取 | 高 | `teacher-service.js` | 结果缓存 + 进行中 Promise 缓存 |
| 查询失败后永久无法重试 | 中 | `rating-display.js` | catch 中删除 `queries` 条目 |
| 背景层缓存雪崩 | 低 | `service-worker.js` | `pendingRequests` 去重 + `finally` 清理 + 20 秒超时 |
| `queries` Map 只增不减 | 低 | `rating-display.js` | LRU 语义，上限 200 条 |
| DOM 重建导致 MutationObserver 失效 | 高 | `content.js` 等三个内容脚本 | 根节点看门狗 + 幂等重扫 + 自节点过滤 |

其中第六个问题是项目自查时发现的高优先级缺陷：点击"查询教学班"后站点重建整个内容区，重建后的 DOM 脱离原观察根节点所在文档树，观察器从此失效。修复方式是每秒检查一次根节点引用，替换后重新挂载观察器并主动触发一次全量扫描，配合已处理行重置与旧按钮清理，保证重扫幂等。

## 8. 局限性与后续方向

### 已知局限

- **依赖选课页 DOM 结构**：识别规则依赖 `table.table.table-hover`、`tbody tr.body_tr`、`td.jsxm` 和表头"教师"，站点改版后需要同步维护；
- **数据是静态快照**：查老师网站没有后端 API，`teachers.csv`、`gpa.json`、评论 CSV 都是站长更新的静态文件，不是实时数据库；
- **无教师详情页**：查老师没有教师详情 URL，只能跳转到自动搜索页；
- **同名同学院仍可能无法区分**：若两位教师姓名、学院都相同，候选列表仍需用户人工确认；
- **缓存时效**：查询结果缓存 24 小时，缓存期内不重新拉取数据；
- **关键词规则简单**：仅基于本地关键词子串匹配，无法理解上下文，可能误匹配（如"不垃圾"仍会命中"垃圾"）。

### 后续方向

- 将识别规则改为可配置映射，降低站点改版维护成本；
- 对关键词规则增加否定词过滤与短语优先级，减少误匹配；
- 增加结果导出或对比视图，方便多课程横向比较；
- 为查老师数据增加本地增量缓存与手动刷新入口；
- 若查老师开放 API，可切换到更稳定的接口。
